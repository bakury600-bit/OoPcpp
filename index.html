Lecture 1 — C++ Functions

01

Function: جزء من كود C++ ينفذ مهمة محددة وله اسم وصفي، وقد يعيد قيمة. يساعد أسلوب Top-down design على تقسيم المشكلة الكبيرة إلى مهام أصغر.

  • Standard functions: دوال جاهزة ضمن مكتبات؛ دوال الرياضيات في <cmath> مثل pow(x,5).
  • User-defined function: دالة يكتبها المبرمج. تتكون من Function Header وFunction Body.
  • الصيغة: return_type functionName(parameter_list) { statements; return value; }
  • void تعني أن الدالة لا تعيد قيمة. مثال: void show().
  • Prototype: تصريح يعرّف المترجم باسم الدالة ونوعها ومعاملاتها قبل استخدامها.

Lecture 2 — Conditional Operator & Default Parameters

02

condition ? expression1 : expression2 هو ternary operator؛ ينفذ التعبير الأول إذا الشرط true وإلا ينفذ الثاني. مثال: x = (y < z) ? y : z;

  • Default parameter: قيمة افتراضية لمعامل عند عدم تمرير قيمة له.
  • المعاملات الافتراضية تكون في نهاية قائمة المعاملات فقط (trailing arguments).
  • مثال: int power(int n, int k=2)؛ الاستدعاء power(5) يستخدم k=2.
  • يجب أن يكون Prototype للدالة قبل استخدامها إذا كان تعريفها لاحقاً.

Lecture 3 — OOP Concepts, Overloading, Reference

03
  • Object: كيان/نوع بيانات يضم خصائص (data) ودوال (methods)، ويمكن تمثيل شخص أو مكان أو حساب مصرفي.
  • مبادئ OOP المذكورة: Encapsulation, Inheritance, Polymorphism.
  • فوائد OOP: Modularity, Information hiding, Code reuse, Easier debugging.
  • Function overloading: عدة دوال بالاسم نفسه مع اختلاف عدد أو أنواع المعاملات. الاختلاف بنوع الإرجاع فقط غير مسموح.
  • Call by reference: استخدام & في معامل الدالة للتعامل مع المتغير الأصلي؛ التغيير يظهر خارج الدالة. أما call by value فيعدل نسخة فقط.

Lecture 4 — Structures and Classes

04
  • Array: يخزن عناصر من النوع نفسه في مواقع متجاورة.
  • Structure: نوع يعرّفه المستخدم لتجميع بيانات قد تكون من أنواع مختلفة، ويُنشأ باستخدام struct.
  • يمكن أن يحتوي struct على Data Members وMember Functions.
  • أعضاء struct تكون public افتراضياً، بينما أعضاء class تكون private افتراضياً.
  • public: يمكن الوصول إليه من خارج الكلاس. private: الوصول المباشر له من خارج الكلاس ممنوع. protected: متاح للكلاس والكلاسات المشتقة، وليس عبر object عادي.
  • Encapsulation: جمع البيانات والدوال ضمن وحدة واحدة. Data hiding: تقييد الوصول المباشر للبيانات، عادة باستخدام private ودوال public.

Lecture 5 — Classes, Objects, Static Members

05
  • الكلاس مخطط (blueprint) لإنشاء objects؛ والـ object هو instance من class.
  • الدوال المعرفة داخل class تكون inline افتراضياً؛ يمكن تعريف الدالة خارجه باستخدام ClassName::function().
  • :: هو Scope Resolution Operator.
  • Getter/Accessor لقراءة البيانات، وSetter لتعيينها أو تعديلها.
  • يمكن عمل overloading لدوال الأعضاء.
  • يمكن أن يحتوي class على object من class آخر.
  • static data member: نسخة واحدة مشتركة بين جميع objects من الكلاس، ويُفضّل الوصول لها باسم الكلاس مثل P::c.

Lecture 6 — Encapsulation & Data Hiding (Part 2)

06
  • Encapsulation يجمع data members وmember functions داخل class واحد.
  • Data hiding يمنع التعديل المباشر على البيانات الداخلية من خارج الكلاس.
  • تُستخدم public functions مثل setData() وdisplay() للتحكم بالوصول.
  • يمكن التحقق من صحة القيم قبل تخزينها، مثل رفض إيداع مبلغ غير موجب أو سحب مبلغ أكبر من الرصيد.
  • الفرق: Encapsulation = grouping؛ Data hiding = access restriction.

Lecture 7 — Constructors, Destructors, Copy Constructor

07
  • Constructor: دالة عضو خاصة تُستدعى تلقائياً عند إنشاء object؛ اسمها نفس اسم class ولا تملك return type.
  • Default constructor: constructor لا يحتاج معاملات. يمكن عمل overloading للـ constructors.
  • إذا لم يكتب المبرمج أي constructor، يوفر المترجم default constructor وفق الحالة الموضحة بالمحاضرة.
  • Destructor: اسمه اسم الكلاس مسبوق بـ ~، لا يعيد قيمة ولا يأخذ معاملات، ويُستدعى تلقائياً عند تدمير object لتحرير الموارد.
  • بالنطاق المحلي، destructors تعمل بترتيب عكسي لترتيب constructors.
  • Copy constructor: ينشئ object جديداً بالاعتماد على object موجود من النوع نفسه. الصيغة الشائعة: ClassName(const ClassName& other).
